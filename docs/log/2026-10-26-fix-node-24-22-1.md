# fix(node): require node 24.22.1 for the october 21 security release

Issue: — · PR: (este) · Autor: Rubén

## Decisiones

- **D-nueva · Node fijado a la versión de parche en `.nvmrc` y `engines`** (precisa D114 y D131) — `.nvmrc` pasa de `24` a `24.22.1`, y `engines.node` de `>=24.11.0 <25` a `>=24.22.1 <25`. **Por qué:** con solo `24`, `actions/setup-node` usa la versión que el runner ya tiene en caché, y el 2026-10-24 la CI corría la 24.21.0, vulnerable. Con la versión exacta, la CI usa la misma que la imagen de la API (#69), y `engineStrict` hace que `pnpm install` rechace un Node vulnerable en cualquier máquina. **Costo:** cada release de seguridad de Node se sube a mano en tres lugares a la vez: `.nvmrc`, `engines` y la imagen base de `apps/api/Dockerfile` (esta última la propone Dependabot). Las versiones de seguridad no esperan los 14 días de D131.

## Historial

- 2026-10-26: **Release de seguridad de Node.js del 2026-10-21 → PR.** La 24.22.1 corrige 10 CVE, entre ellas la [CVE-2026-111497](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) (alta): el descompresor Brotli de `node:zlib` escribe fuera de su buffer con datos malformados, lo que puede llevar a ejecución remota de código. El 2026-10-25, Cloudflare publicó reglas de emergencia en su WAF para cuerpos de petición en Brotli. **Nos toca porque** `body-parser`, que Express usa en la API, descomprime cuerpos `Content-Encoding: br` con `node:zlib`.
  - **Ya estaba parchado:** la imagen de la API (#69) usa la 24.22.1.
  - **No aplica:** el front corre en el runtime de Cloudflare, el *billing guard* en el runtime administrado de Cloud Functions, y staging todavía tiene la imagen de ejemplo de Google.
  - **Vulnerable:** la CI (24.21.0) y la máquina de Rubén (24.20.0); `pnpm dev` levanta la API en todas las interfaces de la red. Este PR cubre la CI; las máquinas se actualizan a mano.
  - **Para el hito 3:** cuando el dominio de la agencia esté en Cloudflare, revisar las reglas administradas del WAF.
